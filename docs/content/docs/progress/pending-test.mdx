# 待测试

- 画布多图节点：一次生成多张图片时应收进同一个节点，可切换主图并分别查看；删除当前主图后，节点展示、下载、裁剪、作为参考图再次生成以及保存后重进画布，都应一致使用自动切换后的新主图，不得继续引用已删除图片。
- Canvas Agent Skill 与引用：Agent 面板应能查看、启用和管理可用 Skill；发送画布节点引用后，对话中的引用预览与消息元数据应正确保存，刷新或恢复历史会话后仍能识别原节点与附件。
- 语言与画布工具：默认显示中文，在普通页面切换英文后主要页面、弹窗和画布操作文案应完整同步变化并在刷新后保持，画布页不应显示语言切换按钮；进入画布默认是移动工具，拖动空白处应移动视图，但点击和拖动节点仍能正常选中、移动节点；手动切到选择工具或在移动工具下按住 Ctrl 时，拖动空白处应改为框选，按住空格则始终临时移动画布。
- 顶栏入口：普通页面和画布页顶栏都不应再出现「文档」按钮；画布页不显示语言切换，普通页面的语言、版本和 GitHub 入口，以及两处的插件、偏好设置、主题、快捷键和账号入口仍应正常显示与使用。
- 首次部署：改掉 `ADMIN_PASSWORD` 与 `JWT_SECRET` 后启动，用管理员登录 `/admin` 添加模型渠道并指定各模型能力；未配置渠道前，画布与生图工作台的模型选择器应提示「服务端未配置模型，请联系管理员」，配置后应能正常选到模型。
- 账号与登录：注册、登录、退出应正常；关闭注册后注册入口应禁用；账号设置的昵称编辑区只应显示一次「昵称」，并可修改密码（原密码错误应提示「原密码不正确」，新密码少于 6 位应被拒）；配置 Linux.do 后可授权登录，已登录账号可绑定与解绑，未设密码时解绑应被拒绝并提示先设密码。
- Passkey：在 HTTPS 或 localhost 环境下可添加 Passkey，添加后可用它免密登录、重命名、删除；账号没有密码且只剩最后一个 Passkey 时删除应被拒绝；纯 HTTP 域名下 Passkey 按钮不应出现。
- Cloudflare Turnstile：管理后台可分别开启登录、注册和第三方登录后补邀请码三个验证码开关，开启的页面应在验证成功后才提交；Passkey 登录与 Linux.do 登录也应遵守登录开关，三个开关互不影响。缺少 Site Key 或 Secret Key 时后台不得保存为开启状态，公开接口不得下发 Secret Key。
- 账号自助注销：账号设置里的注销操作必须二次确认；仍拥有团队或尚未退出团队时应被拒绝。申请成功后当前账号应在所有设备立即退出，24 小时内用原凭据登录会提示账号正在自助注销，确认登录后取消注销并换发新令牌，旧令牌不得复活；超过冷静期后用户的画布、素材、插件、文件、任务、Agent、Passkey 和第三方绑定均应清除，管理后台只保留不占用户名及登录凭据的「已注销」墓碑。管理员重新启用时必须设置全新的用户名与密码，注销期间并发写入不得留下孤儿文件或零引用物理对象。
- 多设备同步：在 A 设备创建画布、添加素材、安装节点插件、修改偏好设置，B 设备登录同一账号后应能看到相同内容；一端删除画布，另一端同步后应消失；同一个插件在不同账号之间不应互相覆盖。
- 服务端生成任务：发起生成后任务应在服务端执行并显示进度；生成中断网、刷新页面或关闭标签页后重新进入，应恢复原任务进度而不是重新生成；同一次生成不重复扣算力点；点击取消应真正中止。
- 跨设备恢复生成任务：A 设备发起生成后立即在 B 设备登录进入对应画布或工作台，应看到任务仍在进行并继续跟进度，完成后结果落到正确位置；任务对应的节点已被删除时应安静丢弃，不报错。
- 画布刷新恢复已结束的任务：生成过程中任务在服务端跑完（或失败）后再刷新画布，仍是「生成中」的节点应拿回结果显示成图片/视频，失败的节点应显示服务端返回的失败原因而不是「页面刷新后生成已中断」，失败任务的算力点应已原路退还且不重复退；画布上早就完成的历史节点不应被重新拉一遍结果，生图与视频工作台也不应把已结束的历史任务当成待恢复任务重新接回。
- 画布文本节点走任务队列：在画布上生成文本时，内容应边生成边逐段出现在节点里（不是转圈等到结束才一次性出字）；生成到一半刷新页面、关掉标签页再回来或换设备登录进入同一张画布，节点应先拿回已经生成出来的那一半，然后接着把剩下的内容写完，全程只扣一次算力点；节点上的「重试」走同一条路径，重试按次计费；点击「停止」应真正中止服务端任务，已经生成的半截内容保留，算力点原路返还。反复用同一次操作重发（断网重试）不应重复生成也不应重复扣费。
- 服务端视频生成：视频任务提交后重启服务端进程，应继续轮询同一个上游任务并最终返回结果，不重新发起生成。
- 生成任务事件流：同时跑多个生成任务（例如画布上几个节点一起生成，或生图工作台一次生成 4 张）时，浏览器到服务端只应保持一条 `/api/v1/jobs/stream` 连接，不应再看到按任务的定时查询；所有任务的进度、文本增量与最终结果都应从这条连接推回来，页面里其它请求不会因为连接被占满而卡住。全部任务结束后这条连接应自动断开，再发起新任务时重新建立。
- 生成任务事件流断线补齐：生成过程中断网、切后台、把网络掐断一段时间再恢复，或者在生成中途刷新页面，重新连上后应把断线期间发生的状态变化和已经生成出来的文本一次补齐，然后接着往下写；断线期间已经跑完的任务重连后应直接拿回结果，而不是一直停在「生成中」。
- 生成任务事件流兜底：如果部署环境的反向代理会掐断或缓冲 SSE（前端连不上事件流），生成不应一直转圈——应自动退化成低频（约 5 秒一次）查询把任务收敛掉，结果照常回填；网络恢复后应自动切回事件流推送。
- 生成任务事件流隔离：用 A 账号的令牌只能订阅到 A 自己的任务，拿不到其他账号的任务状态与文本内容；未登录访问该接口应返回 401。
- 可编辑分享完整画布与计费：所有者创建或修改可编辑链接时应能开启「由我支付算力点」，只有同时开启可编辑、匿名访问和房主代付时才可开启「允许匿名用户编辑」。已登录协作者进入后应看到与所有者大致相同的完整画布工具并与其他端实时同步；匿名用户只有在上述条件全部满足时才能进入完整可编辑画布。房主代付开启时，图片、视频、音频、文本以及插件的图片、视频、文本生成都扣房主算力点；关闭时，已登录协作者第一次执行扣点操作前应能取消，或选择「同意并不再提示」后改扣自己的点，匿名用户不得绕过。
- 可编辑分享任务与个人资产：已经打开分享画布的协作者应自动接管其他端后来发起的生成任务，批量生图的根节点和来源配置节点也应正确结束 loading；刷新后仍能恢复同一分享中其他人发起的任务，房主也应能从自己的任务列表恢复并取消这些任务，分享降为只读后原发起者仍可取消已提交任务。登录协作者应能看到自己的资产，插入个人图片或视频时应先复制到房主空间，再同步给其他协作者；匿名访客不应看到个人资产入口。
- 分享画布 Agent 与权限收回：完整分享画布应提供系统模型与受限本地 Agent。房主代付开启时，登录和匿名访客都可使用系统模型且扣房主算力点；未代付时只允许登录访客在确认自费后使用。每个访客只能看到自己的会话，房主和其他访客看不到；匿名访客应看到「历史保存在当前浏览器、可能丢失，建议登录」的提示，刷新同一浏览器后仍能恢复。受限本地 Agent 不得调用账号级站点工具、跳转页面或靠 URL 参数自动连接，导入或生成的媒体应复制到房主空间。链接被停用、降为只读、关闭匿名编辑或自然过期后，界面和后台循环都应立即收权，已建立的 SSE/WebSocket 连接主动断开，旧会话不得继续动画布或沿用旧付款方。
- 分享协作状态与只读节点菜单：房主和访客同时打开画布时，两边左上角都应显示相同的协作人数，访客右上角操作应与普通画布一样使用图标按钮而不是整排文字。只读访客点击节点应出现只读菜单，只提供信息、下载和查看大图/媒体等不会修改画布的操作；拖拽、缩放、编辑、删除、生成与连线仍必须被拦截。
- 算力点：管理员配置模型算力点后，用户生成应按模型与张数扣点；给画质档位配置加价后，选高画质生成应按「基础价 + 档位加价」扣除；余额不足应提示「算力点不足」；生成失败应自动返还并在流水中留下扣除与返还记录。
- 云空间：账号默认 100MB，账号设置里应显示用量进度条；上传或生成使得超出配额时应被拒绝并提示已用量与上限；删除画布或素材后用量应下降；相同图片重复上传不应重复占用；管理员可在用户管理里调整单个用户的配额。
- 生成历史保留策略：后台可分别配置总历史条数、图片保留天数、图片保留条数以及同时命中时取最大值或最小值；总历史默认不限，图片默认 30 天/100 条并取最小值。用户从云空间删除生成图片后，云空间用量应立即下降但历史在期限内仍可显示；服务启动与后台定时清理发现超出图片策略后，只清除媒体并显示「图片已清除」，提示词、参数和任务记录仍在。只要同一归属范围的云空间仍有相同内容（包括删除后重新上传得到的新 fileId），系统不得清历史媒体；删除总历史也不得删除仍在云空间使用的文件。
- 文件内容去重与引用回收：同一图片在同一账号重复上传只保留一条逻辑文件，不同账号、团队、克隆画布和生成历史可各自持有引用，但磁盘或 S3 只保存一份物理对象。删除任一账号、画布或历史不得误删其他引用；分享源图只剩生成历史时保存副本，副本应得到自己的 fileId，之后房主历史过期仍可显示；最后一个云空间和历史引用都消失后才进入延迟回收，删除与重传并发时也不得出现破图或泄漏对象。
- 功能入口开关：管理员在系统设置里关闭视频与音频后，所有用户的顶部导航不应出现「视频创作台」，画布底部工具栏不应出现视频和音频按钮，生成配置节点只剩生图与文本，画布左侧的节点类型筛选与资产分组、资产选择弹窗里也不应出现视频音频选项，偏好设置不再显示对应默认模型与音频参数；重新开启后应恢复。未配置对应模型时也应自动隐藏。
- Agent 入口范围：只有具体画布页面和分享画布可以显示「打开 Agent」入口与右侧 Agent 面板，首页、生图/视频工作台、团队页、管理后台和其它非画布页面均不应出现该按钮，也不应在页面右侧预留空面板。
- 团队时间显示：团队详情、邀请与日志等页面中的创建时间、更新时间应按浏览器本地时区格式化，不应直接显示 `2026-08-03T16:43:25.456Z` 这类 UTC ISO 字符串；切换系统时区后刷新，展示值应随时区变化而服务端原始时间不变。
- 功能入口的边界：隐藏视频后，画布里已有的视频节点应仍能显示和播放，「我的资产」里已有的视频素材应仍可浏览和插入；已处于视频模式的生成配置节点应自动切到第一个可用模式，且实际生成用的也是切换后的模式。
- 模型展示名：管理员给模型配置展示名后（例如实际名 `gemini-3.1-flash-image`、展示名 `Nano Banana 2`），前端各处模型选择器应显示展示名，而生成请求仍使用真实模型名；留空展示名时应显示模型名。
- 管理后台：管理员可管理用户（含调整算力点与云空间配额）、算力点流水（有刷新按钮，且在用户管理调整算力点后能看到最新流水）、系统设置、提示词与素材；生成记录页可跨用户查看提示词、参数、产出缩略图、错误原因与消耗算力点，并可按用户、状态、类型筛选；用户内容页可按用户查看其画布结构与已生成图片。普通用户访问 `/admin` 应被拦截。
- 提示词库：提示词与分类来自服务端，搜索、分类筛选、标签筛选与分页应正常；管理员可在后台维护分类并「立即同步」，同步后前台应看到更新，同步失败时应显示错误原因。
- 移动端画布提示：在移动端（窄屏）新建或打开画布时应弹出提示，说明画布未针对移动端优化并建议使用生图工作台，提供「继续」与跳转两个按钮；勾选「下次不再提醒」后再次进入不应再弹。
- 服务端密钥安全：管理后台读取系统设置时，渠道 API Key 与 Linux.do ClientSecret 应显示为空并提示留空表示不修改；保存时留空不应清掉已有密钥；前端任何请求都不应拿到渠道密钥明文。
- 数据库与文件存储：分别用 `STORAGE_DRIVER=sqlite`、`mysql`、`postgres` 启动应能自动建库建表；`FILE_DRIVER=local` 时文件落在 `DATA_DIR`，配置 S3 相关变量并设为 `s3` 时文件应落在对象存储且直链可正常读取。
- 上传 HEIC 图片：用 iPhone 拍的原图（HEIC）在生图工作台的参考图、视频创作台的参考资产、画布左侧资产面板、画布页拖拽与粘贴、我的资产等任一入口上传，都应能成功并正常显示缩略图，不再出现空白图或上传失败；转码期间应看到「正在处理…」的提示。上传后在账号设置里看云空间用量、在画布上看图片节点尺寸，应与转码后的 JPEG 一致（不是原 HEIC 的体积），把它当参考图发起生成也应正常。文件选择器里应能选中 `.heic` / `.heif` 文件（部分系统上这类文件没有 MIME，只靠 `image/*` 会被过滤掉）。
- 不该被转码的格式：上传 PNG、JPEG、WebP、GIF 时格式与体积应保持原样，不应被转成别的格式；动图 GIF 上传后应仍然会动。AVIF、BMP 等格式应转成 PNG 或 JPEG，其中带透明背景的图转完仍应是透明的。
- 转码失败提示：上传一个损坏的或改名成 `.heic` 的非图片文件，应弹出中文错误提示（例如「HEIC 图片解码失败，请换一张图片或先转成 JPEG」），不应静默失败，也不应把坏文件传到云空间。
- 转码资源按需加载：只上传 PNG/JPEG 时，浏览器网络面板里不应出现 HEIC 解码库（`heic2any`）的请求；第一次上传 HEIC 时才会加载它（约 1.3MB），之后再传 HEIC 不重复下载。Safari / iOS 因为系统自带 HEIC 解码，应该全程都不加载这个库。
- 画布节点缩放稳定性：选中任意节点并反复拖动四角缩放时，节点工具条应在缩放期间隐藏、松开后恢复，页面不应再出现 `Maximum update depth exceeded`。
- Agent MCP 初始化状态：首次进入空白对话或点击「新对话」后，无需先发送消息，对话区应立即显示 Codex 会话准备，并同时列出 `codex_apps`、`infinite-canvas`、`node_repl` 等全部 MCP 服务各自的启动、就绪或失败状态；初始化期间可输入并保留草稿，但发送按钮、上传和回车提交应禁用，全部完成后显示服务数量、恢复发送并复用同一个预热线程；右侧日志应记录同样的真实状态，`starting` 与 `ready` 归入信息且就绪显示绿色成功图标，只有 `failed` 归入错误、`cancelled` 归入警告，模型开始处理后不应残留初始化文案。
- Agent 模型设置：连接 Canvas Agent 后，输入框左下方应显示当前 Codex 模型与推理强度；模型列表应来自当前账号实际可用模型且不显示内部审查模型或重复项，切换模型后强度选项随模型能力更新且无空白选项，刷新页面后保留选择，发送任务时实际使用所选模型和强度；本地控制台与右侧「日志」应记录本轮使用的模型和推理强度。
- Agent 新对话响应：一轮对话完成后点击「新对话」，聊天内容应立即清空并进入空白对话，不出现等待或新建按钮卡顿；后台应立即创建线程并预热 MCP，多个标签页应同步进入空白对话，点击后立即发送也不得误发到上一条会话或重复创建线程。
- Agent 读取画布卡片：读取当前画布完成后，卡片应按非零类型显示文本、图片、配置、视频、音频、分组、其他节点及连线数量，例如「3 个文本、5 张图片、2 个配置、4 条连线」；空画布应显示「当前画布为空」，执行失败时仍应显示错误信息，刷新恢复历史后统计保持一致。
- Agent 首次发送响应：在空白新对话中输入内容并按回车后，输入框应立即清空、用户消息应立即出现在对话中，再显示「正在思考」；线程创建或发送失败时，原输入和附件应恢复；任务运行期间输入的新草稿不应在请求成功后被清空。
- Agent 动态工具信息：执行内置生图、查看图片、命令、文件修改或其他动态工具时，卡片标题应显示具体工具名称；执行失败时正文应显示真实错误原因，刷新并恢复历史对话后仍应保持一致，不再统一显示「工具操作已完成」。
- Agent 画布生图：重启 Canvas Agent 后，其自动生成的工作区 `AGENTS.md` 应同步为最新版指令（用户自行编写的其他 `AGENTS.md` 不应被覆盖）；输入“生成一张图片”时应调用 `canvas_generate_image`，通过当前画布节点创建并运行生成流程；只有明确输入“使用 Codex 内置生图/ImageGen 技能生成”时才允许调用内置能力，Codex App Server 返回的 `imageGeneration` 结果应显示在对话中并作为保持原比例的图片节点添加到当前画布；Agent 不应在没有生成结果时提前声称“已生成”。
- Agent 顶部栏：标题只显示垂直居中的「Agent」，连接、对话、历史、日志、新对话和收起操作应位于同一行；面板较窄时标签仍可横向滚动且操作不应错位。
- Agent Markdown 样式：右侧 Agent 回复中的代码块应为横向占满消息区域、无语言标题和无双层边框的紧凑代码条，单行内容不应保留纵向大面积空白，复制操作仅在悬停时弱化显示；行内代码、链接在浅色和深色主题下应清晰；点击外部链接后应显示中文紧凑确认弹窗，长路径能够正常换行且复制、继续打开和关闭操作可用；点击 `/Users/`、`/home/` 等本地绝对文件路径时应改为提示在系统文件管理器中定位，支持复制路径，且浏览器地址不应跳转为 localhost 文件路径。
- Agent 工具确认模式：右侧面板标题栏不应再显示「工具确认」开关；对话输入框左下方应显示确认模式选择，默认选中「自动确认」，画布写入工具应直接执行；切换为「手动确认」后，画布写入工具应在对话中展示等待确认卡片，并支持批准或拒绝。
- Canvas Agent Codex 升级：启动 Canvas Agent 后应输出 Canvas Agent、内置 Codex 和本机 Codex 版本，实际运行的内置 Codex 应为 0.146.0；内置与本机版本不一致、未安装本机 Codex，或 npm 存在更新版本时应显示对应升级提醒，npm 检查失败不应阻止服务启动；Agent 应能正常连接 Codex、创建或恢复会话、发送消息并调用画布工具，运行中停止任务应只中断当前 turn，随后无需重启 Agent 即可继续发送新任务。
- Canvas Agent Debug：普通启动应通过公共 logger 输出 Info、Warn 和 Error 日志；使用 `npx -y @basketikun/canvas-agent --debug` 启动后还应输出 Debug 日志并显示日志文件路径，终端统一采用“`YYYY-MM-DD HH:mm:ss` 级别 消息 详情”的纯文本单行格式，`~/.infinite-canvas/logs/` 下应按启动日期生成相同格式的 `canvas-agent-YYYY-MM-DD.log`，同一天多次启动应追加到同一文件；日志中不应出现连接 token 或图片 Data URL 原文。
- Canvas Agent Codex 日志：Codex app-server 输出带颜色或样式控制符及 UTC 时间的 stderr 时，本地日志和网页诊断日志应只显示一份 `YYYY-MM-DD HH:mm:ss` 本地时间和干净文本，不应出现重复 ISO 时间或 `[2m`、`[31m` 等 ANSI 转义内容。
- Agent HTTP 诊断日志：网页发送一条普通消息后，本地 Debug 日志不应重复输出 `/health`、`/canvas/state`、`/canvas/activate` 成功请求、流式增量或完整会话响应，只保留 HTTP 请求与 Codex 生命周期摘要；右侧「日志」应以单行时间线展示发送、开始、回复、工具、完成用量和错误，不再输出 userMessage started/completed、流式摘要、重复 threadId 或大段原始 JSON。
- Agent 排查日志：右侧「日志」中的排查视图应显示连接摘要，并可按错误、警告和信息筛选；向下查看日志时仅列表内部滚动，标题、连接状态、筛选数量和操作按钮保持固定；连续相同事件应折叠计数，单条日志可展开查看完整详情；原始 JSON、复制全部、复制最近错误和清空功能应继续可用，浅色与深色主题下均应清晰。
- Agent 排查日志顺序与跟随：日志应按时间从旧到新排列，进入日志或切换筛选时定位到最新事件；停留底部时自动跟随新日志，展开最后一条后应继续停留在完整详情底部，向上浏览后暂停跟随并显示与对话区视觉高度一致的居中圆形向下箭头，新日志数量只在悬浮提示中显示；列表底部不应出现额外留白，点击按钮后回到底部并恢复跟随。
- 画布列表缩略图：画布库里含有图片节点的卡片应显示最多 4 张方形缩略图，图片按画布内顺序去重取前几张；没有图片的画布保持原来的纯文字布局；图片已被删除或换了服务端地址时该张应自动消失而不显示破图；卡片的点击进入、重命名、导出、删除与多选应不受影响。
- Agent 对话统计：用户消息应右对齐并使用透明无气泡的简洁排版，用户和 Codex 两侧均不显示人物头像，消息下方均不显示时间或 Token 信息；输入框上方应居中展示最新一次模型调用的输入、缓存、输出 Token 用量，不显示会话累计值，数值更新时应从旧值平滑滚动到新值而非突然跳变，新建、切换或删除当前会话后应清空旧统计。
- Agent 回复实时显示：在右侧 Agent 发送消息后，用户消息下方应立即出现“正在思考...”，任务运行期间不应闪退；工具完成后应显示 Codex 正在继续处理及已等待时长，等待超过 30 秒时提示可继续等待或停止本轮；Codex 的回复应在当前对话中持续显示，实时事件缺失时也应在任务完成后自动同步完整内容，无需切换到历史或日志再返回对话。模型繁忙等任务失败时应立即结束等待状态，在对话中显示中文错误原因和重试建议，诊断日志不应再把失败轮次记为“处理完成”，刷新历史后错误仍应保留。新建尚未发送首条消息的空会话不应反复出现历史读取失败。
- Agent 对话实时与历史一致性：运行包含思考、命令及画布工具的较长任务，在执行中刷新发起页面或打开第二个页面时，已出现的用户消息、思考过程、工具卡和回复前缀均应保留并继续更新；同一思考或工具只显示一张卡片，任务结束及再次刷新后内容、顺序和状态应一致。切换页面焦点不能改变本轮画布工具目标，发起页面断开后不得把图片或写操作转交其他画布，使用相同页面身份重连后才能继续处理。
- Agent 流式交互性能：发送长回复时文字应连续平滑出现，输入框、滚动和画布操作不应随回复变长而明显卡顿；长历史会话中只有当前流式消息持续更新，屏幕外消息不应造成明显布局压力；任务完成后应通过 SSE 自动同步完整历史，不再持续请求 `/health` 轮询状态。
- Agent 过程时间线：新建 Agent 对话后 Codex 应生成可读思考摘要，并在运行时依次显示中文的思考摘要、执行计划、命令执行、网页搜索、文件修改和画布工具活动；思考摘要的图标、标题和箭头应稳定保持在同一行，默认收起且无边框，点击箭头后才展开 Codex 实际返回的具体摘要，其中 Markdown 强调、列表和代码应正确渲染而非显示原始符号，多行代码块和文本流程图应保留原始换行并允许横向滚动，完成事件不应再用「已完成分析」覆盖已经收到的摘要；同一轮连续命令应合并为显示数量的无边框折叠行，折叠时不显示命令预览，单条展开后直接显示详情，多条展开后可逐条查看工作目录、耗时、退出状态和运行输出；其他工具调用继续使用紧凑卡片排版，状态图标、标题和状态文字保持在同一行；结构化任务进度不应混在对话时间线中，而应独立放在对话区下方、Token 统计上方，支持展开和折叠，并逐项实时更新「待处理」「进行中」「已完成」状态；新任务生成时默认展开，任务结束后保留最新结果，同一计划更新不应生成重复内容；文件详情展示文件路径与新增/修改/删除动作，工具详情不应出现请求 ID、英文工具名或原始 JSON；一轮对话结束自动同步历史以及刷新页面后从历史中 resume 对话时，思考摘要、命令和工具过程记录仍应完整保留并保持相同展示。
- Agent 权限控制：输入框可选择「请求批准」「自动审查」「完全访问」；请求批准模式下，Codex 编辑工作区外文件、执行受限命令或访问网络时应在对话中显示审批卡片，支持拒绝、允许一次和本会话允许，并能依次处理多个并发请求；提交决定后卡片应保持禁用等待，只有 Codex 确认处理后才移除；等待审批时刷新页面，未处理的审批卡应自动恢复且不能让任务永久卡住；自动审查模式应仅将需要用户决定的风险操作送入审批；完全访问必须先显示风险确认，启用后可访问网络和本机文件且不再请求审批；选择应在刷新后保留。
- Agent 历史记录：点击记录卡片应直接进入对应对话，不再显示「进入」按钮；可勾选单条或全选多条记录并批量删除，删除当前对话后聊天内容应清空。
- Agent 默认新对话：每次进入任一画布并连接 Agent 后，对话区应保持空白且不自动恢复上一次会话，并在后台创建新线程、预热 MCP；需要继续旧对话时可在「历史」中主动选择恢复。
- Agent 当前画布优先：在已打开某个画布时要求 Agent 创建、修改、整理或生成内容，Agent 应直接读取并操作当前画布，不应先调用 `canvas_list_projects` 或使用 `site_navigate` 重复进入画布；只有明确要求查看或切换其他画布时才允许查询画布列表并导航。
- Agent 图片消息：发送一张或多张图片附件后，图片应紧跟用户文字并在消息右侧显示为约 40px 的紧凑缩略图，不再撑大消息区域，单击缩略图应打开大图预览，打开或关闭预览不应改变消息间距或产生额外空行；任务运行中、完成同步历史、切换页面及重新进入历史对话后都应显示浏览器本地保存的图片缩略图，不应消失或把 attachmentId、附件使用说明等内部上下文回显到用户消息中；删除历史会话后应同步清理对应缩略图。
- 画布文本复制：在 Agent 对话或节点信息详情中用鼠标选中文字后，按 `Ctrl/Cmd + C` 应复制所选文本，不应触发画布节点复制；未选中文字且焦点位于画布时，原有节点复制快捷键应保持可用。
- Agent 工作目录指令：`canvas-agent/agent-instructions.md` 应作为独立维护源；重启 Canvas Agent 后，当前工作目录应自动生成 `AGENTS.md`；新建对话发送消息时，Codex 日志中的用户消息只包含本轮请求和必要的附件上下文，不再重复整段 Infinite Canvas 前置提示词，画布及工作台工具仍可正常调用。
- 画布文本设置：文本节点和生成配置节点切换到文本模式后应显示推理强度设置，可选择自动、低、中、高、极高；选择自动时默认 OpenAI Responses 请求不应携带 `reasoning`，选择其他档位时应携带所选强度，刷新画布后节点设置应保留；文本模型自定义调用脚本应能读取 `reasoningEffort`，OpenAI 模板应按自动或指定档位正确组装请求。
- 生图工作台参考图：将一张或多张图片拖入参考图区域后应直接上传并显示缩略图；拖入非图片文件应忽略，拖动过程中区域应显示高亮提示，放下文件不应导致浏览器打开或替换当前页面。
- 视频创作台参考资产：将图片、MP4/MOV 视频或 MP3/WAV 音频拖入任一参考资产区域后，应按文件类型自动上传到对应列表；当前拖入区域应显示高亮提示，原有数量、大小、时长和格式限制应继续生效。
- 画布组装提示词：输入或连接超长提示词后，浮层正文高度不应继续撑大，内容应可在正文区域内滚动查看和编辑，标题及关闭按钮保持可见。
- 画布节点提示词：图片等节点下方的提示词超过输入区域高度后，鼠标悬停在输入区域内滚动应查看提示词内容，不应缩放画布。
- 画布节点提示词回显：单图或多图生成完成后，切换选择生成结果的根节点及任一子节点，下方输入区域都应继续显示生成时的提示词；切换到其他节点再选回来后也不应清空。
- 画布生成配置：连接文本节点后连续点击生成（包含失败重试），组装提示词不应重复追加上游文本；在生图、文本、视频、音频之间切换时，实际请求应始终使用当前面板展示的对应类型模型。
- 画布左侧元素列表：点击元素整行应平滑定位并选中对应节点；有内容的图片元素应显示预览按钮，点击后打开大图弹窗且不触发画布定位。
- 配置与用户偏好：导出 JSON 后应包含渠道、默认模型、生成偏好、提示词来源和 WebDAV 配置；在修改当前配置后重新导入该文件，应恢复导出时的设置，错误 JSON 文件应提示格式不正确。配置文件包含 API Key 和 WebDAV 凭据，不应公开分享。
- 模型渠道协议：渠道编辑可选择「火山方舟」并自动填入方舟接口地址；任意名称的生图模型应按方舟 JSON 格式提交参考图，任意名称的视频模型应按方舟任务格式提交和查询，不再依赖模型名包含 `doubao`、`seedream` 或 `seedance`；1080p 不应再因模型名包含 `fast` 被禁用，参考视频应允许最大 200MB、总像素 409600-8295044，并继续校验官方宽高、比例和时长限制。
- 图片编辑弹窗：遮罩、切图和裁剪连续滚轮缩放时，图片与遮罩应保持同步且不再闪烁、短暂消失或跳动；遮罩画笔圆心应始终固定在鼠标位置，仅直径随缩放变化，缩放后仍可准确涂抹、拖动切分线和调整裁剪框。
- 提示词中心布局：页面标题及提示词总数应居中；连续输入搜索文字时应在停止输入约 300ms 后再查询；桌面端分类与标签应在左侧独立滚动，右侧搜索框下直接展示提示词卡片；标签数量较多时不能继续向下挤压提示词，窄屏下应恢复上下排列且内容不溢出；不再显示「我的提示词」Tab，收藏提示词应直接加入我的资产。
- 提示词详情弹窗：封面和参考图应固定显示在上方，复制及加入资产操作栏固定在底部，只有中间的标签、描述及提示词内容区域可以滚动；弹窗宽高应受视口限制且不超出屏幕。
- 提示词来源：6 个内置来源应从 Image Prompts 统一仓库读取，更新后数量依次为 323、494、53、76、126、129；提示词仍按 6 个来源分组并可独立启用，来源内可继续按 `tags` 筛选。添加标准 JSON URL 后应能查看内容，填写非数组 JSON 或不可访问地址时应显示失败，并继续保留该来源上一次成功缓存的内容。
- 提示词来源界面：来源应以卡片列表展示，启用开关位于左侧，数量、同步状态和上次成功时间作为次级信息显示，查看、拉取及自定义来源编辑/删除操作使用带文字按钮；底部定时拉取区域应保持独立边框布局。
- 画布提示词库：不应再显示「我的提示词」分组；不展开任何公共来源直接搜索其中的提示词，匹配项应自动显示；点击「插入画布」后应创建正文正确且标题保持为提示词标题的文本节点。
- 全站 Agent：新增 `generation_get_status` 工具，画布生成节点可按 `nodeIds` 查询，生图和视频工作台提交后会返回 `taskId` 并可查询排队、运行、成功或失败状态；需验证查询只由当前活动标签页返回。
- 本地 Agent 多标签页隔离：同时打开两个不同画布并连接同一个 Agent，分别聚焦标签页后通过 MCP 读取和修改画布，操作应只落在当前聚焦页面；网页面板发起的整个 Codex turn 应固定操作发起页面，即使中途聚焦另一标签页也不能切换目标；非运行状态关闭当前页面后应回退到最近聚焦且仍连接的页面，运行中关闭发起页面则不得把操作转交其他画布，只有同一页面身份重连后才能继续；其他页面回传同一请求结果应被拒绝。
- 本地 Agent 多标签页会话同步：所有标签页共享同一个站点级 Codex 活跃线程；任一页面发送消息、新建、恢复或删除会话后，其他页面应同步活跃线程和聊天记录；Agent 输出仅显示在事件所属线程，运行中不能新建、恢复、删除或再次发送任务。
- 本地 Agent 运行状态同步：在一个标签页运行较长 Codex 任务，等待某张工具卡显示「工具完成」后再打开或刷新第二个标签页；第二个标签页应立即显示 Codex 正在运行并禁用发送，整轮结束后两个标签页同时恢复；工具卡只显示「工具完成」，整轮结束由「本轮完成」表示。
- 本地 Agent 图片附件落画布：在右侧 Agent 上传参考图并要求基于商品信息创建生图流程，附件应创建为保持原比例的真实图片节点，分析提示词应创建为文本节点，二者都应连接到生成配置节点；刷新页面后参考图仍可显示并参与生成。任务中途切换到其他标签页时，附件只能写入发起任务的标签页；若发起标签页关闭，附件读取应失败且不能落入其他画布。
- Agent 对话滚动：从历史或日志切回对话、恢复其他会话时应自动定位到最新消息；手动向上浏览后应显示与日志完全相同尺寸、位置和样式的居中圆形向下箭头，新消息不强制打断阅读，对话底部不应出现额外留白，点击按钮后平滑回到底部并继续跟随新消息。
- Agent 消息区分：用户消息应在右侧使用透明无气泡排版，AI 回复应在左侧使用无头像的开放式 Markdown 排版；长文本、多张附件、错误消息及浅色/深色主题下均应清晰且不溢出。
- 画布 Agent 模式切换：面板标题位置应可在「系统模型」与「本地 Agent」之间切换，选择刷新后保留；管理员在后台关闭画布 Agent 后不应出现切换入口，只保留本地 Agent；带 `agentUrl` 参数打开的画布应直接进入本地 Agent 模式。
- 系统模型操作画布：在系统模型模式下让它新建/修改/删除节点或连线，对话里应显示具体工具名、参数与执行结果，画布应在工具执行完成后自动出现对应改动，不需要手动刷新；未配置联网搜索密钥时空会话说明里不应出现「联网搜索」。
- 系统模型断线恢复：任务运行中刷新页面、关闭面板、断网或换设备重新进入，应能看到任务仍在执行并自动补齐断线期间产生的消息与画布改动；执行完成后再进来也应看到完整结果，不会重复执行或重复扣费。
- 系统模型会话管理：可新建、切换、删除会话，会话列表只显示当前画布的会话；删除正在执行的会话应一并中止；运行中点击停止按钮应显示「已中止本次执行」。
- 系统模型计费提示：输入框上方应显示「每条消息 N 点」，悬停能看到「发一条消息扣 N 点，这条消息触发的多轮思考与工具调用都不再额外扣点」的说明，并显示当前余额；页面各处都不应再出现「按轮计费」「每轮」的说法。发一条会触发多轮工具调用的消息，余额应只减少一条消息的钱；余额不足时发送应显示服务端返回的「算力点不足」，服务重启后的旧会话应提示「服务已重启，请重新发送消息」。
- 系统模型选模型：输入框左下方应有模型选择器，只列出管理员配置的文本模型（不出现生图、视频、音频模型）并标出每个模型每条消息消耗的算力点；切换后发送消息应真的用所选模型执行，扣的点数按所选模型单价扣一次，输入框上方的「每条消息 N 点」也跟着变；每个会话记住自己在用的模型，切换会话、刷新页面、换设备登录同一账号后选择都还在；会话执行中选择器应禁用，本轮用的模型在发送时就已确定。用管理员接口直接传生图模型或不存在的模型也不应生效，应回落到默认模型。
- Agent 默认模型偏好：偏好设置里应有独立的「Agent 默认模型」，它决定新建会话起手用哪个模型，跟随账号云端同步；没设置过时沿用管理员在后台配置的全站默认；管理员把用户选中的模型下线或停用后，该会话再发消息应自动回落到默认模型继续跑完，不应报错卡死，面板上显示的也应是回落后的模型。
- 系统模型等待提示：发送消息后等待提示应按当前实际进度显示「正在思考」，正在执行工具时显示具体工具名（如「正在新建节点」「正在生成图片」「正在联网搜索」），不应再一律显示「系统模型正在操作画布」。
- 系统模型行内引用：把画布节点拖到面板输入框上松手，应在当前光标处插入一个引用标签（不是追加到末尾），标签显示节点标题、没有标题时显示类型名；一条消息里可以插多个引用并穿插在句子任意位置，同一个节点可以引用多次；光标停在标签末尾按一次退格应整块删掉整个标签，不会把「图片1」删成「图片」；图片、文本、视频、音频、配置各类节点都能被引用。发送后服务端记录的引用顺序应与句子里的出现顺序一致，标记也停在原来的位置；引用的节点在发送前被删掉时应提示「引用的画布节点已不存在」。
- 系统模型引用不带图片：只用引用（不上传附件）发消息时，模型上下文里不应出现任何图片数据——即使当前模型标注了「支持视觉」也不应该；模型要看图必须自己调用看图工具。
- 系统模型引用高亮定位：鼠标移到输入框里的引用标签或已发送消息里的引用上，画布上对应的节点应立刻出现高亮描边，移开即恢复；点击引用时如果该节点已经在视口里，画面不应乱动，节点不在视口里才平移过去，并且只平移不改缩放。整个过程都不该改动用户已有的选中节点（先选中几个节点再去悬停、点击引用，选中集合应原样保留）。引用的节点被删掉后，标签应置灰划掉，悬停能看到「引用的节点已从画布中删除」，点它不再定位也不报错。切换会话、新建会话、关闭面板或离开画布后，画布上不应残留高亮。
- 系统模型上传图片：点击输入框左下角的图片按钮或直接粘贴图片可上传，上传的图占用户自己的云空间配额，输入框里能看到缩略图并可移除，发送后在对话记录里也能看到自己发过的图；当前模型没有标注「支持视觉」时应明确提示换模型或移除图片，不允许静默把图丢掉；agent 的工具应能按 `server:xxx` 的 storageKey 引用到这些图（例如让它「用这张图建一个节点」）。
- 系统模型图片拖回画布：把面板里的图片（输入框里的缩略图或对话记录里发过的图）拖到画布上松手，应在鼠标松开处的画布坐标建出图片节点；该节点复用原图的 storageKey，云空间用量不应增加，也不应产生第二份文件。
- 后台配置多家联网搜索：系统设置的「联网搜索」区可新增多条服务，每条能选服务商（Exa / Tavily）、填备注名、API Key、权重和接口地址（留空用官方地址），并可单独启停与删除；一条都没配、或配了但都没填 Key 时，下方提示应是「当前联网搜索不会生效」，配好保存后变为已生效。保存后重新打开页面，Key 应显示为空（服务端脱敏），此时直接再保存一次不应把已配好的 Key 洗掉；调整多条服务的顺序或增删其中一条后保存，各条的 Key 也不应串到别的服务上。
- 联网搜索自动切换服务商：同时配置 Exa 与 Tavily，把权重高的那条的 Key 故意改成错的再保存，让 Agent 联网搜索或读取网页，应仍然正常返回结果（自动用了另一条）；把两条的 Key 都改错时才应提示失败。两家单独配置时，搜索与读网页都应能正常工作。
- 画布 Agent 读取网页：让 Agent 查一个答案藏在页面深处的问题（例如某个接口的具体参数），它应先联网搜索拿到候选网址，再对其中一两条调用「读取网页」把正文读回来，而不是把搜到的每条都读一遍；对话里应能看到该工具的网址参数与执行结果。读到超长页面时返回里应标出被截断，Agent 不应把半篇文章当成全文下结论。
- 读取网页的地址限制：让 Agent 读取 `http://127.0.0.1:8080`、`http://192.168.1.1`、`http://169.254.169.254` 这类本机或内网地址，应被拒绝并给出中文提示，不应真的发出请求；`file://`、`ftp://` 等非 http/https 地址同样应被拒绝。未配置任何搜索服务时，Agent 不应拿到「读取网页」工具。
- 搜索结果带回图片：让 Agent 联网搜索图片类问题（例如「找一张金毛幼犬的照片」），搜索结果里应带回图片地址——用 Exa 时图片跟在各条结果上，用 Tavily 时是本次搜索的一组图，两家都应能拿到可用的图片链接。
- Agent 导入网络图片：让 Agent 把搜到的图片放到画布上，它应先用「导入网络图片」把图片地址存成服务端文件，再用返回的 storageKey 建图片节点；画布上应真的出现这张图，账号设置里的云空间用量应相应增加，把该图当作生图参考图也应能正常生成。同一张图重复导入不应重复占用空间。
- 导入网络图片的边界：内网或本机地址（`http://127.0.0.1/x.png`、`http://192.168.1.1/x.png`）应被拒绝；把一个网页地址或改名成 `.png` 的非图片文件交给它，应提示不是图片而不是存进云空间；超过 10MB 的图片应中断下载并提示换一张；heic、avif、tiff、bmp 等格式应明确提示暂不支持并建议换 png/jpeg/webp（服务端不做转码），Agent 收到提示后应自己换一张图重试；云空间配额用满时导入应提示云空间不足。
- Agent 命令记录：命令执行中应显示运行状态；完成后，同一轮相邻命令应合并为「已执行 N 条命令」折叠行且默认不显示原始命令，单条展开后直接显示完整详情，多条展开后可分别查看命令、输出和退出状态；对话结束或刷新后分组与记录不应消失。
- 「系统模型」工具调用整组折叠：让 Agent 做一件要连调多个工具的事（例如「先看画布，再建节点，再生成一张图」），执行中面板上只应有一行，且写的是当前正在做什么（「正在读取画布」「正在生成图片」），不是笼统的「正在执行工具」；跑完后这一行收成「已执行 N 个操作 · 耗时 X 秒」并默认折叠，点一下才展开，展开后每个工具的参数、结果与状态仍和原来一样齐全，其中有失败的应在这一行标出失败数量。刷新页面或换设备重新进入会话后，折叠与展开的表现应保持一致；本地 Agent 的命令分组行为不受影响。
- Agent 生成默认设置：偏好设置里应出现「Agent 生成默认设置」，可配默认生图模型、尺寸、画质、张数、背景与默认生文模型；改完后换设备登录同一账号应保留（跟随账号云端同步）。让 Agent 生成图片且它自己没指定参数时，应按这里配的默认执行；模型明确指定了某个参数时以模型的为准。这一组默认与工作台的「默认生图模型 / 生成偏好」互不影响。
- 「系统模型」待用户确认：轮数耗尽时面板应出现确认卡片，说明这条消息已经跑了多少轮、继续会再扣多少点算力（计费口径仍是每条消息扣一次，续跑等于再发一条）；Agent 想改画布标题时应出现另一张卡片，显示它想改成什么标题以及理由。等待确认期间输入框应给出「有请求在等你确认」的提示且发不出新消息，但中止按钮仍可用；点「批准执行」后会话应接着往下跑，点「拒绝执行」应收尾结束。等待确认时刷新页面或换另一台设备进来，这条待确认请求应还在；在一台设备上批准后，另一台设备上的卡片应随之消失。
- 「系统模型」生成工具的全量参数：按明确要求让 Agent 生成（例如「用某某模型、透明背景、high 画质，生成两张 16:9 的图」「生成一段 5 秒 720p 不带配音的视频」「用某某音色慢速朗读这段话」），后台生成记录里的模型与参数应与要求一致，产出也应符合。指定一个不存在或能力对不上的模型（例如拿文本模型去生图）时不应报错，而是回落到系统默认模型照常生成，对话里能看到实际用的是哪个模型。
- 「系统模型」文本生成工具：让 Agent 写一篇长文（例如「写一篇八百字的产品介绍放到画布上」），它应调用文本生成工具并在画布上建出内容完整的文本节点；后台生成记录里应能看到一条来源为 agent 的 text 任务，并按该模型单价扣了点（这一步的扣费独立于发消息那一次）。让它写短句、标题、清单这类内容时应直接自己写进节点，不该为此多花一次钱。
- 会话标题模型：管理后台系统设置里可单独指定「会话标题模型」（和 Agent 主模型并列）。配好后新建会话发第一条消息，会话列表里的标题应在一两秒内变成模型起的短标题（十来个字以内、不带引号），算力点流水里不应因此多出一条扣除；同一个会话后续发消息不应再改标题。把标题模型留空、或指定一个连不上的模型，发消息都应照常成功，标题回落成第一句话的截断。
- 剩余轮数与续跑：给一个要做很多步的任务（例如「把画布上所有节点重新排版并逐个补上说明」），Agent 应能感知到剩余轮数并优先做要紧的事；轮数用完时会话应停在等待确认而不是直接结束。批准后应接着往下做，且算力点流水里会多出一条按当前模型单价的扣除；把余额清空后再批准，应提示「算力点不足」并仍停在等待确认，不会偷偷跑一段免费的。
- 画布标题的主动改名：在一张标题还是「无限画布 3」或「未命名画布」的画布上让 Agent 做点事，它可以在弄清意图后主动把标题改成贴合内容的名字，不需要确认，但整个会话只会这样改一次；之后再让它改标题都应先征求同意。把画布名字改成「无限画布精选」这类自己起的名字后，Agent 的任何改名都应先征求同意，拒绝后标题保持原样。
- 服务重启与等待确认：会话停在等待确认时重启服务端，回来后这个会话不应还挂在等待状态，而应给出「服务已重启，待确认的请求已失效，请重新发送消息」的中文说明，并可以直接重新发消息继续用。
- 后台邀请码管理：管理后台左侧应有「邀请码」入口。批量生成时可以填数量、每码可用次数、赠送算力点与备注，一次生成多个；生成后应弹出结果窗口按行列出这一批码，「复制全部」应把它们一次性复制到剪贴板，关掉窗口后列表里能看到这些新码，也能逐个复制。列表应显示码值、已用/上限、赠送算力点、启用状态、备注与创建时间，用满次数的码标出「已用完」；行内开关可直接启用/禁用，编辑可改次数、算力点与备注（次数不能改到已用次数以下），删除有二次确认；点「使用记录」应弹出抽屉列出谁在什么时候用掉了这个码、当时送了多少算力点，没人用过时显示空状态。
- 注册需要邀请码：管理后台系统设置的「注册与登录」里有「注册需要邀请码」开关。开启后注册表单应多出邀请码输入框，留空提交会被前端拦下，填错应展示服务端返回的中文原因（例如邀请码不存在、已停用、已用完），填对应能注册成功并按该码的配置赠送算力点；关闭后输入框应消失，且能直接注册。
- 第三方登录补邀请码：开启「注册需要邀请码」后用一个没注册过的 Linux.do 账号授权登录，回调页应停在「填写邀请码」而不是直接登录，此时刷新或关掉页面都应仍是未登录状态；填对邀请码后才建号并回到发起登录的页面。填错应展示服务端原因且仍未登录；授权放太久过期后再提交，应展示服务端给的过期提示，点「重新登录」能重新走一遍授权；点「放弃并返回」应回到原页面且保持未登录。已经注册过的 Linux.do 账号仍应直接登录，不要求邀请码。
- 实时 WebSocket 单连接：打开一张画布并让它同时有画布协作、团队状态、生成任务与「系统模型」Agent 四类实时内容时，浏览器网络面板里到服务端应只有一条 `/api/v1/realtime` 的 WebSocket 连接，不应再看到四条并行的 SSE；画布变更、团队余额、生成进度与 Agent 消息都应从这一条连接推回来，任一频道退订不应影响其它频道。
- 实时票据鉴权：连接前应先调 `POST /api/v1/realtime/tickets` 换票，票据只在 URL 里出现一次且 30 秒内有效；同一张票据被用第二次应握手失败，过期票据、伪造票据与不带票据的升级请求都应被拒绝且服务端不崩；未登录且非分享访客时不应能取到票据。
- 反向代理 Upgrade 透传：用仓库自带的 nginx 配置（或自己的反代）部署后，画布应能直接建起 WebSocket 并保持在线，不应出现「连上就立刻断开」；同时普通接口请求（登录、保存画布、上传）应不受升级头影响，不出现偶发 400。
- 实时降级路径：把反代的 Upgrade 透传去掉或直接屏蔽 WebSocket 端口，画布协作、团队状态、生成任务与 Agent 四类实时内容都应自动退回 SSE 并继续工作；再把 SSE 也掐掉（代理缓冲或阻断事件流），应继续退回低频轮询把状态收敛掉，功能不中断只是变慢；环境恢复后应能自动切回 WebSocket。
- 实时断线重连：连接期间断网、切后台、休眠一段时间再恢复，或在协作中途刷新页面，重连后各频道应补齐断线期间的变化——画布应拿到最新 revision 的内容、生成任务应按序号补齐、Agent 会话应补上断线期间的消息与画布改动，不应出现重复消息或永远停在旧状态。
- 实时权限隔离：用 A 账号的票据不应订阅到 B 账号的画布、团队、生成任务与 Agent 会话频道；分享访客的票据只能订阅其分享链接对应的那张画布，订阅团队、任务或 Agent 频道应被拒绝；分享链接在连接期间被停用或改成只读时，对应订阅应当场收到失效通知并断开。
- 画布保存仍走 HTTP 与版本校验：两个端同时修改同一张画布保存时，仍应由服务端的 revision 原子版本检查挡下静默覆盖，落后的一端应收到冲突并合并后重试；WebSocket 只负责推送变更与 presence，把 WebSocket 断开后保存与冲突判定行为应完全不变。
- 实时长期稳定性：让一张画布连着 WebSocket 挂机数小时（跨越反代与浏览器的空闲超时），期间偶尔操作一次，连接应保持可用或自动重连并补齐，不应出现静默掉线后再无推送；长时间运行后服务端不应出现连接数、订阅或票据的内存持续增长。
- 多实例部署限制：当前实时总线是进程内的，只保证单实例部署完整推送。多实例（或多副本容器）部署时，连到不同实例的两个端之间实时推送会不完整，需要确认此时前端仍能通过降级与刷新拿到正确内容、计费与画布版本判定仍以数据库为准；共享总线（如 Redis adapter）本版本未提供，不要按已支持多实例来验收。
